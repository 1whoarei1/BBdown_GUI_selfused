# 阶段 5+ 参考功能储备（来自 bbdown-webui 对比）

以下功能确认“我们可以做”，但不纳入当前初版收口主线，先记录，后续按优先级实现。

## P1：可直接复用到桌面端的功能

1. 批量添加任务
   - 多行输入，一行一个 URL / BV / AV / EP / SS
   - 批量提交多个下载任务
   - 说明文案提示并发/队列行为

2. 任务列表增强
   - 进行中 / 已完成 分区展示
   - 任务封面
   - 最近状态消息
   - 当前分 P / 总分 P
   - 成功 / 失败 / 已取消 图标
   - 删除已完成任务

3. 简单模式 / 进阶模式
   - 简单模式仅显示常用参数
   - 进阶模式显示完整 BBDown 选项

4. 高级参数动态表单
   - 基于 metadata 驱动表单渲染
   - 支持依赖字段显示/隐藏
   - 便于后续扩展 BBDown 参数而不手写大量 UI

5. 多任务历史与清理
   - 历史记录
   - 重试失败任务
   - 清理已完成任务
   - 复制命令

## P1：桌面端比参考 WebUI 更适合实现的功能

6. 停止任务
   - 参考项目明确受 BBDown JSON API 限制无法很好中断
   - 我们桌面端直接管本地进程，应继续把 stop 做成差异化能力

7. 打开输出目录
   - 桌面端天然适合做
   - 属于高频实用能力

8. 本地工具路径自动检测与向导
   - BBDown / ffmpeg / mp4box / aria2c
   - 首次启动向导

## P2：后续再考虑

9. 任务队列 / 有限并发
   - 不照搬参考项目的全并行提交策略
   - 应做成桌面端可控队列

10. 更完整高级参数 UI
   - UserAgent
   - aria2c 路径与参数
   - mp4box 路径
   - upos host / force replace host
   - save archives
   - config file
   - debug

11. 视觉与体验增强
   - 深浅色模式切换
   - 更成熟的移动/窄窗适配
   - 更细的任务状态展示

## 明确不照搬的部分

- 不把参考项目的进度条视为真实能力来源
  - 我们仍然以“状态 + 阶段 + 当前 P / N + 日志”为核心
- 不采用“无限并行提交”作为默认策略
- 不依赖 BBDown JSON API 服务模式作为主架构

## 当前策略

先不打断当前主线开发：
- 继续收口 stop 生命周期
- 补齐 parser 结构字段
- 做 4 条真实链接回归
- 完成可用初版

等初版稳定后，再从本清单中按 P1/P2 逐步实现。
